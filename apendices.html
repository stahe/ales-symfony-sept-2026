    13. Apéndices

    13.1. Instalación de PHP

    Los ejemplos y el caso de estudio requieren [PHP] 8.4 o una versión posterior ([Symfony] 8 lo exige), con las extensiones [intl] (formato de números y fechas, ejemplo 16, y mensajes ICU, ejemplo 22), [pdo_mysql] (acceso a [MySQL], ejemplo 28 y caso de estudio), [mbstring], y [openssl]. Se han probado con la versión 8.4.

    En [Windows], lo más sencillo es [Laragon] (laragon.org), que instala [PHP], [Composer], un servidor [MySQL] y la herramienta de administración [HeidiSQL]. Si la versión de [PHP] proporcionada es anterior a la 8.4, descargue una versión más reciente desde windows.php.net/download (versión Thread Safe, archivo [.zip]) y extráigala en la carpeta [bin\php] de [Laragon]; el menú PHP / Version de [Laragon] permite entonces seleccionarla. El menú PHP / Extensions activa una extensión con un solo clic ([intl], [pdo_mysql]). La terminal de [Laragon] (botón Terminal) admite los comandos [php], [composer] y [mysql].

    Sin [Laragon], extraiga el archivo comprimido de [PHP] en una carpeta ([C:\php]), agregue esta carpeta a la variable de entorno [Path], luego cree el archivo de configuración [php.ini] copiando [php.ini-development], y elimine el punto y coma que comenta las líneas de las extensiones necesarias:

    1
2
3
4
    extension=intl
extension=mbstring
extension=openssl
extension=pdo_mysql

    En [macOS], el administrador de paquetes [Homebrew] instala [PHP] y sus extensiones estándar: [brew install php]. En [Linux] ([Ubuntu]), la versión que ofrece la distribución suele ser más antigua; el repositorio [ppa:ondrej/php] proporciona las versiones más recientes:

    1
2
    sudo add-apt-repository ppa:ondrej/php
sudo apt install php8.4-cli php8.4-intl php8.4-mbstring php8.4-mysql php8.4-xml php8.4-curl php8.4-zip

    Verifique la instalación en una consola nueva:

    1
2
    php -v
php -m

    El primer comando debe mostrar un número de versión igual o superior a 8.4 (por ejemplo, [PHP 8.4.12]); el segundo enumera las extensiones cargadas, entre ellas [intl] y [pdo_mysql]. El comando [php --ini] indica qué archivo, [php.ini], se está utilizando.

    13.2. Composer

    [Composer] es el administrador de bibliotecas de [PHP] (getcomposer.org). Lo proporciona [Laragon]; para [Windows], pero sin [Laragon], se utiliza su instalador ([Composer-Setup.exe]); para [macOS], use [brew install composer]; para [Linux], siga las instrucciones de la página getcomposer.org/download. Verifique la instalación:

    1
    composer -V

    Comandos útiles en una carpeta de proyecto (la que contiene [composer.json]):

    1
2
3
4
5
    composer install              # instala las bibliotecas del proyecto (carpeta vendor)
composer show                 # las bibliotecas instaladas
composer update               # pasa a las versiones más recientes permitidas por composer.json
composer require name/package # agrega una biblioteca al proyecto
composer dump-autoload        # reconstruye el cargador de clases (después de agregar una carpeta de clases)

    [Composer] descarga las bibliotecas del repositorio [Packagist] (packagist.org): se requiere conexión a Internet durante la instalación. Si está detrás de un proxy corporativo, especifique el proxy mediante las variables de entorno [HTTP_PROXY] y [HTTPS_PROXY]. La carpeta [vendor] no se copia de una máquina a otra (puede contener rutas absolutas y es voluminosa); se vuelve a crear con [composer install]. Por eso no se incluye en los materiales del curso. La carpeta [examples] tiene su propia carpeta [vendor], compartida por los 28 ejemplos; el caso de estudio tiene la suya.

    El caso de estudio utiliza el componente [Runtime] de [Symfony], que también es un plugin de [Composer]: este componente es el que genera el archivo [vendor/autoload_runtime.php] que lee [public/index.php]. [Composer] solicita permiso para ejecutar un plugin; el archivo [composer.json] de la aplicación lo concede (sección [allow-plugins]). En [Linux], [Composer] se niega a ejecutar plugins cuando lo inicia la cuenta [root], a menos que la variable de entorno [COMPOSER_ALLOW_SUPERUSER] tenga el valor [1]: sin ella, faltaría el archivo [autoload_runtime.php] (consulte «Problemas frecuentes» en el caso de estudio). Es preferible no trabajar con la cuenta [root].

    13.3. Instalación de Visual Studio Code

    [Visual Studio Code] se descarga desde code.visualstudio.com. Agregue tres extensiones (menú View / Extensions):

    • PHP Intelephense: autocompletado de código, navegación por el código (incluido el de [Symfony], ubicado en la carpeta [vendor]) y reporte de errores;
    • Twig Language 2: resaltado de sintaxis y autocompletado para las vistas [Twig] (archivos [.html.twig]);
    • YAML (de [Red Hat]): resaltado de sintaxis y validación de los archivos de configuración ([config/packages/*.yaml]) y de los diccionarios ([translations/*.yaml]).

    La extensión PHP Debug permite ejecutar el código paso a paso con el depurador [Xdebug] (una extensión de [PHP], que debe instalarse por separado: xdebug.org).

    Abra la carpeta [examples] o la carpeta del caso de estudio (menú File / Open Folder). La terminal integrada (menú Terminal / New Terminal) permite iniciar las aplicaciones y ejecutar los comandos [php bin/console ...] sin salir del editor.

    13.4. Instalación de MySQL con Laragon

    [Laragon] instala un servidor [MySQL] listo para usar en [Windows], junto con la herramienta de administración [HeidiSQL]. Después de la instalación:

    • el botón "Start All" inicia el servidor [MySQL] en el puerto 3306;
    • el usuario [root] no tiene contraseña: estos son los valores de la variable [DATABASE_URL] de los archivos [.env] del ejemplo 28 y del caso de estudio ([mysql://root:@127.0.0.1:3306/...]);
    • el botón Database abre [HeidiSQL], donde el menú File / Run File SQL ejecuta los scripts [dbpersons.sql] (ejemplo 28) y [dbrdvmedecins2.sql] (caso de estudio).

    En [Linux] o [macOS], instale [MySQL] o [MariaDB] con el administrador de paquetes del sistema y ejecute los scripts con el cliente de línea de comandos [mysql]. El controlador [pdo_mysql] funciona con ambos sin ninguna configuración. En [Linux], la cuenta [root] de [MariaDB] suele estar configurada para iniciar sesión solo mediante la cuenta del sistema [root] ([sudo mysql]): entonces se crea un usuario para las aplicaciones y este se indica en la variable [DATABASE_URL] de su archivo [.env] ([mysql://course:course@127.0.0.1:3306/...]):

    1
    sudo mysql -e "CREATE USER 'course'@'localhost' IDENTIFIED BY 'course'; GRANT ALL ON *.* TO 'course'@'localhost';"

    Con [MariaDB], también se indica su versión en la variable [DATABASE_URL] ([serverVersion=10.11.2-MariaDB] en lugar de [serverVersion=8.0.32], por ejemplo): [Doctrine] adapta el SQL que escribe a la base de datos utilizada.

    13.5. Instalación de curl

    [curl] viene incluido con [Windows] 10 y 11, [macOS] y la mayoría de las distribuciones de [Linux]. En [PowerShell], debe escribir [curl.exe], no [curl]: en las versiones antiguas de [PowerShell], [curl] es un alias de otro comando ([Invoke-WebRequest]), que tiene opciones diferentes. En el símbolo del sistema de [Windows] ([cmd]), las comillas de una cadena JSON se escriben [\"] (ejemplo 11), y una URL que contenga [&] debe ir entre comillas dobles.

    13.6. La herramienta symfony

    [Symfony] ofrece una herramienta de línea de comandos, el programa [symfony] (Symfony CLI), que no es necesaria para seguir este documento, pero a la que se hace referencia en toda la documentación. Se instala siguiendo las instrucciones de la página symfony.com/download: en [Windows], con el administrador de paquetes [Scoop] ([scoop install symfony-cli]); en [macOS], con [Homebrew] ([brew install symfony-cli/tap/symfony-cli]); en [Linux], con el administrador de paquetes del sistema. Los comandos más útiles:

    1
2
3
4
    symfony check:requirements      # ¿la configuración de PHP es adecuada para Symfony?
symfony new my-project --webapp # un nuevo proyecto completo (ver la introducción)
symfony server:start            # un servidor de desarrollo (http://127.0.0.1:8000)
symfony console debug:router    # equivalente a php bin/console debug:router

    Su servidor de desarrollo hace lo mismo que [php -S localhost:8000 -t public], con algunas ventajas: localiza por sí mismo la carpeta [public], puede servir el sitio en HTTPS (después de [symfony server:ca:install]), puede ejecutarse en segundo plano ([symfony server:start -d], luego [symfony server:stop]) y selecciona la versión de [PHP] del proyecto cuando hay varias versiones instaladas. El servidor integrado en [PHP], utilizado en este documento, tiene la ventaja de no requerir instalación.
