    5. Internacionalización

    Una aplicación internacionalizada muestra su texto en el idioma del usuario. El caso de estudio está en francés e inglés. El principio es simple: las vistas ya no contienen texto, sino claves ([MENU.HOME]), y un diccionario para cada idioma asocia un texto a cada clave. El idioma seleccionado se almacena en una cookie.

    [Symfony] incluye un componente de traducción, el Translator, que ya encontramos en el Ejemplo 09 para los mensajes de validación. Sus diccionarios se almacenan en la carpeta [translations], con un archivo por dominio e idioma: [validators.en.yaml] (el dominio de los mensajes de validación, Ejemplo 09), [messages.en.yaml] (el dominio predeterminado, el de nuestros textos). El formato YAML admite claves anidadas: así, los diccionarios de las versiones [ASP.NET Core MVC], [NestJS], [Spring MVC], [Flask] y [Laravel] del caso de estudio, salvo por la sintaxis. Para la sintaxis de los propios mensajes, elegimos el formato ICU (International Components for Unicode), un estándar que la extensión [intl] de [PHP] puede interpretar y que, por ejemplo, permite flexionar el texto en plural. El formato de fechas y montos sigue siendo el mismo que en el Ejemplo 16.

    • Línea 5: el idioma predeterminado de la aplicación, que se usa para las solicitudes que no especifican un idioma (Ejemplo 09);
    • línea 6: los idiomas admitidos por la aplicación. Esta lista la usa [Symfony] (el profiler, la generación de rutas localizadas, etc.); nuestro propio código también tiene su propia lista, en el listener [SetLanguage];

Una clave que falta en todos los diccionarios se muestra tal cual: de este modo, cualquier omisión es visible de inmediato en la pantalla.

    # translations/messages+intl-icu.fr.yaml: el diccionario francés.
# messages: el dominio predeterminado; +intl-icu: los mensajes siguen la sintaxis ICU
# ({name}: un parámetro; {n, plural, ...}: un mensaje que depende de un número)
MENU:
    HOME: Accueil
    PRODUCTS: Produits
HOME:
    TITLE: Bienvenue
    HELLO: 'Bonjour {name} !'
    DATE: 'Nous sommes le {date}.'
PRODUCTS:
    TITLE: Nos produits
    NAME: Produit
    PRICE: Prix
    COUNT: '{n, plural, =0 {Aucun produit} one {# produit} other {# produits}} au catalogue.'

    El nombre del archivo consta de tres partes: el dominio ([messages], el dominio predeterminado), el sufijo [+intl-icu], que indica mensajes en formato ICU, y el idioma ([fr]). Las claves se agrupan por tema mediante la estructura de anidamiento de YAML: el elemento de menú “Accueil” tiene la clave [MENU.HOME], con los niveles separados por un punto. Un texto puede contener parámetros, escritos como [{name}], que se reemplazan durante la traducción.

    • Línea 9: los apóstrofos delimitan una cadena YAML; son necesarios cuando el texto contiene caracteres que YAML interpreta (llaves, dos puntos, etc.);
    • Línea 15: un mensaje en plural. [{n, plural, ...}] selecciona una forma según el valor del parámetro [n]: [=0] para exactamente 0, [one] para el singular, [other] para el plural; [#] se reemplaza por el número. Las reglas del plural dependen del idioma, e ICU las conoce: en francés, 0 y 1 son singular, mientras que en inglés, 0 es plural (“0 products”). Esto mejora el “product(s)” utilizado en las versiones anteriores del caso de estudio.

    <?php
// src/EventListener/SetLanguage.php: el idioma de cada solicitud

namespace App\EventListener;

use Symfony\Component\EventDispatcher\Attribute\AsEventListener;
use Symfony\Component\HttpKernel\Event\RequestEvent;
use Symfony\Component\HttpKernel\KernelEvents;

// prioridad 20: después del enrutamiento, antes de los listeners de Symfony que usan el idioma (véase el ejemplo 16)
#[AsEventListener(event: KernelEvents::REQUEST, priority: 20)]
class SetLanguage
{
    // los idiomas admitidos; el primero es el idioma predeterminado
    public const LANGUAGES = ['en', 'fr'];

    public const COOKIE = 'language';

    // el idioma de la cookie [language] si es admitido, inglés en caso contrario
    public function __invoke(RequestEvent $event): void
    {
        $request = $event->getRequest();
        $language = $request->cookies->get(self::COOKIE);
        $request->setLocale(in_array($language, self::LANGUAGES, true) ? $language : self::LANGUAGES[0]);
    }
}

    Este es el listener [SetLanguage] del Ejemplo 16, que esta vez obtiene el idioma de una cookie:

    • línea 11: el listener del evento [kernel.request], con prioridad 20: después del enrutamiento, pero antes de los listeners de [Symfony] que utilizan el idioma de la solicitud (Ejemplo 16);
    • líneas 15–17: los idiomas admitidos y el nombre de la cookie: constantes de clase públicas, accesibles desde otras clases ([SetLanguage::LANGUAGES]);
    • líneas 22–24: el idioma de la solicitud: el de la cookie [language] si existe y es admitido; de lo contrario, inglés. [$request->cookies] es el conjunto de cookies enviadas por el navegador (ejemplo 05); [get] devuelve el valor de una cookie o [null]. [in_array], con [true] como tercer parámetro, compara también los tipos ([===]). [setLocale] establece el idioma de la solicitud: es el idioma que utilizan el traductor, nuestros filtros de formato y el filtro [format_currency] de [Twig].

    A diferencia de [Laravel], [Symfony] no cifra las cookies: la cookie [language] se transmite en texto plano. Esto no es un problema: no contiene información confidencial y el servidor solo acepta los idiomas admitidos. El siguiente ejemplo vuelve sobre la cuestión de cuánta confianza puede depositarse en una cookie.

    <?php
// src/Controller/LanguageController.php: la elección del idioma

namespace App\Controller;

use App\EventListener\SetLanguage;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Cookie;
use Symfony\Component\HttpFoundation\RedirectResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\Routing\Attribute\Route;

class LanguageController extends AbstractController
{
    // GET /language/fr: guarda la elección en una cookie y luego regresa a la página anterior.
    // requirements: un idioma distinto de en o fr no coincide con la ruta (404)
    #[Route('/language/{code}', name: 'language', requirements: ['code' => 'en|fr'], methods: ['GET'])]
    public function change(Request $request, string $code): RedirectResponse
    {
        $response = $this->redirect(self::originPage($request));
        // la cookie: un año de vida, ilegible para el JavaScript de la página (httpOnly),
        // nunca enviada con una solicitud POST proveniente de otro sitio (sameSite lax)
        $response->headers->setCookie(Cookie::create(SetLanguage::COOKIE, $code)
            ->withExpires(new \DateTimeImmutable('+1 year'))
            ->withHttpOnly(true)
            ->withSameSite(Cookie::SAMESITE_LAX));
        return $response;
    }

    // la página de la que venimos (encabezado Referer), de la cual conservamos solo la ruta:
    // redirigir a una dirección completa proveniente de la solicitud permitiría
    // enviar al usuario a otro sitio (vulnerabilidad de "open redirect")
    private static function originPage(Request $request): string
    {
        // parse_url divide una URL en sus componentes (ruta, parámetros...)
        $url = parse_url($request->headers->get('Referer', ''));
        $path = $url['path'] ?? '';
        // "//site.com/..." sería entendida por el navegador como una dirección
        // en OTRO sitio: también se rechaza
        if (! str_starts_with($path, '/') || str_starts_with($path, '//')) {
            return '/';
        }
        return isset($url['query']) ? "$path?{$url['query']}" : $path;
    }
}
    • línea 17: la ruta [/language/{code}]. La opción [requirements] (ejemplo 02) limita el parámetro a los dos idiomas admitidos: [/language/de] no corresponde a ninguna ruta y devuelve un error 404;
    • línea 20: la acción responde con una redirección a la página de la que provino el usuario: el usuario regresa a su página en el nuevo idioma;
    • Líneas 23–26: la respuesta contiene una cookie, que el navegador reenviará con cada solicitud. La clase [Cookie] de [Symfony] la describe: [Cookie::create(name, value)] la crea, y cada método de [with...] devuelve una copia modificada (un objeto inmutable; véase el Ejemplo 03): [withExpires], la fecha de expiración (en un año); [withHttpOnly(true)] la hace invisible para el [JavaScript] de la página; [withSameSite(Cookie::SAMESITE_LAX)] impide que el navegador la envíe con una solicitud POST proveniente de otro sitio. ([httpOnly] y [lax] son, dicho sea de paso, los valores predeterminados de [Cookie::create].) [$response->headers->setCookie] la agrega a la respuesta como un encabezado [Set-Cookie];
    • líneas 33–44: la página de origen se especifica mediante el encabezado [Referer] de la solicitud (la versión con error ortográfico, con una sola [r], es la que se usa en el estándar HTTP), que el navegador completa con la URL de la página que contenía el enlace. Pero este encabezado proviene del cliente, que puede poner en él lo que quiera. Redirigir a ciegas a esta dirección convertiría nuestra aplicación en una redirección abierta: un enlace malicioso con el nombre de nuestro dominio podría enviar al usuario a un sitio malicioso. Por lo tanto, conservamos solo la ruta y los parámetros de la URL (la función [parse_url] de [PHP] la descompone en sus componentes en un arreglo asociativo) y rechazamos cualquier ruta que comience con [//], que el navegador interpretaría como la dirección de otro sitio.

    <?php
// src/Controller/PagesController.php: las acciones no saben nada del idioma:
// proporcionan datos, las vistas los traducen y los formatean

namespace App\Controller;

use App\Model\Product;
use DateTimeImmutable;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[Route(methods: ['GET'])]
class PagesController extends AbstractController
{
    #[Route('/', name: 'home')]
    public function home(): Response
    {
        return $this->render('pages/home.html.twig', ['name' => 'Marie',
            'today' => new DateTimeImmutable('2026-09-23')]);
    }

    #[Route('/products', name: 'products')]
    public function products(): Response
    {
        return $this->render('pages/products.html.twig', ['products' => [
            new Product('Keyboard', 2500),
            new Product('Mouse', 1250),
            new Product('Screen', 114900),
        ]]);
    }
}

    Las acciones son independientes del idioma: proporcionan datos sin procesar (un nombre, una fecha, montos en centavos). La traducción y el formato corren por cuenta de las vistas. La clase [Product] tiene un nombre y un precio en centavos; la extensión [FormatsExtension] es la del Ejemplo 16: su filtro [long_date] escribe una fecha en el formato “completo” del idioma de la solicitud (“Wednesday, September 23, 2026”, “mercredi 23 septembre 2026”), y su filtro [money] escribe un monto.

    Otra forma de elegir el idioma habría sido leer el encabezado [Accept-Language] del navegador (ejemplo 12; [$request->getPreferredLanguage(['fr', 'en'])] selecciona el mejor idioma entre los admitidos).
