Sigue al documento “Introducción paso a paso al framework web [Laravel]” (2026), que a su vez siguió a los documentos “Introducción paso a paso al framework web [Flask],” "Introducción paso a paso al framework web [Spring MVC]," "Introducción paso a paso al framework web [ASP.NET Core MVC]" y "Introducción paso a paso al framework web [NestJS]" (2026). Este documento permanece dentro del universo [PHP] pero cambia de framework:

    • el framework [Laravel] se reemplaza por el framework [Symfony] 8.1, que sigue utilizando el lenguaje [PHP] (versión 8.4 o posterior);
    • las vistas [Blade] se reemplazan por vistas [Twig], el motor de vistas de [Symfony];
    • la validación mediante las reglas de [Laravel] y las solicitudes de formulario ([FormRequest]) se reemplaza por el componente Validator de [Symfony] (restricciones, escritas como atributos de [PHP]) y por su componente Form, que describe los formularios mediante clases;
    • los guardias, los middleware y los componentes [Gate] de [Laravel] se reemplazan por el componente Security de [Symfony]: firewalls, autenticadores, roles, hash de contraseñas y un limitador de intentos, complementado con la biblioteca [firebase/php-jwt] para los tokens JWT;
    • Sin embargo, los componentes middleware no existen en [Symfony]: los listeners de eventos se utilizan para intervenir en el procesamiento de la solicitud;
    • el ORM [Eloquent] se reemplaza por [Doctrine], un ORM utilizado con [Symfony], que a su vez se apoya en [MySQL].

    El documento sigue de cerca la estructura del curso de [Laravel]: primero, numerosos proyectos pequeños, cada uno centrado en un solo concepto, seguidos de un caso de estudio completo (una aplicación web para agendar citas en un consultorio médico) con todos los archivos comentados en detalle. Los ejemplos tienen los mismos números y abordan los mismos temas que en los cursos de [Laravel], [Flask], [Spring MVC], y [ASP.NET Core MVC]: un lector familiarizado con alguno de estos cursos puede comparar los frameworks ejemplo por ejemplo. Sin embargo, esto no es indispensable: este documento se basta a sí mismo y no supone ningún conocimiento previo de esos frameworks. Los únicos requisitos son una comprensión básica de la programación web (el protocolo HTTP, el lenguaje HTML) y los fundamentos del lenguaje [PHP] (variables, arreglos, funciones, clases). El curso “Introducción al lenguaje PHP7 mediante ejemplos” (2019) presenta el lenguaje en sí para quienes necesiten aprenderlo primero; las novedades de [PHP] 8 que se usan aquí (propiedades promovidas, clases [readonly], atributos, enumeraciones, argumentos con nombre, el operador nullsafe, etc.) se explican la primera vez que aparecen.

    1.1. El papel de Symfony en una aplicación web

    Una aplicación web suele construirse en capas, y cada capa se comunica únicamente con las capas vecinas:

    • la capa web recibe las solicitudes HTTP del navegador y le devuelve páginas HTML. Es la capa que [Symfony] nos ayuda a escribir;
    • la capa de negocio contiene las reglas de negocio de la aplicación (por ejemplo, “un paciente solo puede tener una cita próxima”). No sabe nada de la web: podría servir igualmente a una aplicación de línea de comandos;
    • la capa de acceso a datos (capa DAO, por Data Access Object) lee y escribe en la base de datos. Usaremos [Doctrine], el ORM (Object Relational Mapper) asociado con [Symfony], que asigna las filas de las tablas a objetos [PHP].

    La capa web sigue a su vez el patrón MVC (Model-View-Controller):

    • el controlador (C) es una clase [PHP] cuyos métodos, llamados acciones, se encargan cada uno de un tipo específico de solicitud (por ejemplo, [GET /schedule]). Una acción lee los parámetros de la solicitud, procesa la solicitud a través de la capa de negocio y luego selecciona la vista que se mostrará;
    • el modelo (M) es el conjunto de datos que la acción pasa a la vista;
    • la vista (V) es un archivo [Twig] (extensión [.html.twig]): una página HTML que contiene expresiones [{{ ... }}] e instrucciones [{% if %}], [{% for %}]..., que el motor [Twig] reemplaza por los datos del modelo.

    Una nota sobre la terminología, para evitar confusiones: en [Symfony], las clases que representan las tablas de la base de datos se llaman entidades (carpeta [src/Entity]). En este documento, el término “modelo” se referirá siempre al modelo de la vista (los datos que se pasan a una vista) o, en el capítulo 2, al modelo de la acción (los datos que esta recibe). El término “plantilla” designa la vista común de la que heredan otras páginas (capítulo sobre las vistas).

    El procesamiento de una solicitud sigue los pasos numerados del diagrama:

    • 1: El navegador envía una solicitud, por ejemplo HTTP o [GET /schedule?doctorId=1&day=2026-09-26];
    • 2: El servidor web recibe la solicitud y la pasa a la aplicación [Symfony] a través del archivo [public/index.php]. Durante el desarrollo, este servidor es el que incluye [PHP], iniciado con el comando [php -S localhost:8000 -t public]; en producción, será un servidor como [nginx] o [Apache], asociado con [PHP-FPM]. El archivo [public/index.php] pasa la solicitud al núcleo (kernel) de la aplicación, que la hace pasar por una serie de eventos: intervienen clases de [Symfony] y de la aplicación, así como listeners (sesión, seguridad, idioma, etc.). Uno de ellos compara la ruta solicitada con las rutas de la aplicación y selecciona la acción responsable de esta solicitud: es el enrutamiento;
    • 3: La acción solicita a la capa de negocio los datos que necesita; si es necesario, la capa de negocio recurre a la capa DAO, que consulta en SQL la base de datos [MySQL];
    • 4: La acción construye el modelo M de la vista e indica al motor [Twig] que genere la página (método [render]);
    • 5: La página HTML generada por la vista es la respuesta de la acción, que [Symfony] devuelve al navegador.

    [Symfony] es, junto con [Laravel], uno de los dos grandes frameworks web del mundo [PHP]. Gratuito y de código abierto, creado en 2005 por Fabien Potencier (y la empresa francesa SensioLabs), funciona en cualquier lugar donde funcione [PHP] ([Windows], [Linux], [macOS]), y [PHP] funciona con casi todos los proveedores de alojamiento web. [Symfony] es, ante todo, una colección de unos cincuenta componentes, bibliotecas independientes (solicitudes y respuestas HTTP, enrutamiento, consola, formularios, validación, seguridad, etc.), tan apreciadas que otros proyectos las utilizan: [Laravel] mismo se construye sobre varias de ellas, y los lectores del curso anterior ya las han encontrado. El framework [Symfony] ensambla estos componentes mediante bundles (paquetes de integración) y un contenedor de servicios que crea los objetos de la aplicación. En comparación con [Laravel], [Symfony] toma decisiones claras: nada de fachadas ni funciones globales, sino servicios obtenidos mediante inyección de dependencias; configuración explícita en archivos YAML; atributos de [PHP] ([#[Route]], [#[Assert\NotBlank]]...) para describir el código; un ORM, [Doctrine], que separa los objetos de su persistencia. Es un framework reconocido por su rigor, su documentación y su política de versiones: una versión menor cada seis meses, una versión de “soporte a largo plazo” cada dos años y la garantía de que una aplicación sin advertencias de obsolescencia pasará a la siguiente versión mayor sin modificaciones. [Symfony] puede crear servidores que devuelven JSON a un cliente [JavaScript] ([Angular], [React], [Vue.js], [Flutter]...) así como aplicaciones web tradicionales, donde el servidor genera las páginas HTML y el navegador se limita a mostrarlas. Es este segundo caso de uso el que examina este documento.

    Una particularidad de [PHP] explica buena parte de [Symfony]: la aplicación se reconstruye en cada solicitud y luego se descarta (ejemplo 01). [Symfony] compensa este costo compilando su configuración una sola vez en código [PHP], que se almacena en un caché (carpeta [var/cache]). Volveremos a esto con frecuencia.

    1.2. Herramientas utilizadas

    Los ejemplos se escribieron y probaron con las siguientes herramientas (su instalación se describe en el apéndice):

    • [PHP] 8.4 (sirve cualquier versión 8.4 o posterior), con las extensiones [intl], [mbstring], [openssl], y [pdo_mysql];
    • [Composer] 2, el administrador de bibliotecas de [PHP];
    • el editor [Visual Studio Code], con las extensiones [PHP Intelephense] (análisis de código), [Twig Language 2] (vistas) y [YAML] (archivos de configuración);
    • un navegador moderno ([Chrome], [Firefox], [Edge]);
    • la herramienta de línea de comandos [curl], que muestra las respuestas HTTP sin procesar (viene incluida con [Windows] 10 y 11);
    • un SGBD, [MySQL] (o [MariaDB]), por ejemplo, el de [Laragon] en [Windows], a partir del capítulo sobre el acceso a datos y para el caso de estudio. En [Windows], [Laragon] instala [PHP], [Composer], y [MySQL] de una sola vez.

    [Symfony] y las demás bibliotecas no forman parte de [PHP]: [Composer] las descarga del repositorio [Packagist] durante la instalación (por lo tanto, ese día debe estar conectado a Internet) y las coloca en una carpeta [vendor].     [Symfony] se instala normalmente creando un proyecto completo con el comando:

    1
    composer create-project symfony/skeleton my-project

    o con la herramienta de línea de comandos de [Symfony] (el programa [symfony]; véanse los apéndices): [symfony new my-project --webapp]. [Composer] descarga entonces el esqueleto de una aplicación [Symfony], seguido de sus bibliotecas. El esqueleto contiene además [Symfony Flex], un plugin de [Composer] que, cada vez que se instala una biblioteca ([composer require twig]), escribe sus propios archivos de configuración a partir de plantillas publicadas en línea. Así es como se inicia un proyecto real. Con fines de aprendizaje, este método tiene un inconveniente: los archivos aparecen solos, sin que se sepa para qué sirven. Por ello, los ejemplos de este documento parten del otro extremo: el ejemplo 01 es la aplicación [Symfony] más pequeña posible, y cada ejemplo añade solo los archivos que necesita, escritos y comentados a mano. El caso de estudio final sigue la estructura de una aplicación [Symfony] estándar.

    Para ejecutar los ejemplos, primero instale sus bibliotecas (una sola vez) en una ventana de terminal abierta en la carpeta [examples]:

    1
    composer install

    [Composer] crea la carpeta [examples/vendor], compartida por los 28 ejemplos, y el archivo [composer.lock], que registra las versiones exactas instaladas (véase el caso de estudio). La carpeta [common] contiene el framework CSS [Bootstrap] ([common/bootstrap]), compartido por los ejemplos que dan formato a sus páginas (a partir del ejemplo 15), y el controlador que lo sirve ([common/BootstrapController.php]; véase el ejemplo 15).

    • [config]: configuración: los bundles de la aplicación ([bundles.php]), la configuración de cada uno (carpeta [packages]), las rutas ([routes.yaml], ejemplo 02), los servicios ([services.yaml], ejemplo 06);

    Para ejecutar un ejemplo, abra un terminal en su carpeta (en [Visual Studio Code]: haga clic con el botón derecho en la carpeta del ejemplo y seleccione “Open in Integrated Terminal”) y escriba:

    1
    php -S localhost:8000 -t public

    Todos los ejemplos escuchan en el puerto 8000: solo puede ejecutar uno a la vez (o debe cambiar el puerto: [php -S localhost:8001 -t public]). Detenga el servidor con [Ctrl-C] en el terminal. No es necesario reiniciar el servidor después de modificar un archivo [PHP], una vista o la configuración: los cambios surten efecto en la siguiente solicitud (ejemplo 01).

    Cuando abre la carpeta [examples] en [Visual Studio Code], la extensión [PHP Intelephense] analiza todos los archivos, incluidos los de [Symfony] en la carpeta [vendor]: en cada archivo, puede aprovechar la finalización de código, la navegación a la definición de una clase o método (tecla [F12]) y el reporte de errores. Como todos los ejemplos tienen sus clases en el espacio de nombres [App], la extensión puede señalar clases “duplicadas”: esto no tiene efecto en la ejecución, ya que cada ejemplo se ejecuta de forma independiente. Para evitar estas advertencias, basta con abrir la carpeta del propio ejemplo.
